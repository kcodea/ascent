# 2026-10-08 — God Mode: a Practice learning playground

**Owner ask:** "i want to create another couple of options for practice mode. lets call it God Mode: in this option
you get 999 gold, infinite timer, and the dev tuner that we have available in the scene builder." The point: "give
players access to all the money, search and print out minions in the shop to buy, to start learning interactions."

Spec: `docs/superpowers/specs/2026-10-08-god-mode-design.md`. Plan: `docs/superpowers/plans/2026-10-08-god-mode.md`.
Oracle: R-GODMODE-01..08 (`packages/rules/src/registry/approved/foundation.ts`).

## What shipped

- **Practice screen:** God Mode | Sandbox Mode side by side, each with Select + description, then Start. Sandbox
  options are greyed and inert until Sandbox is selected (`PracticeOptions.tsx`). God Mode ignores them and plays
  every hero, Unlimited health, every tribe, no timer (`godPracticeConfig`), leaving the Sandbox draft untouched.
- **The run** (`packages/sim/src/godMode.ts`): an ordinary practice lobby run stamped `sandbox: true` (the existing
  write barrier: no save/Continue, upload, XP, crate, replay) + `godMode: true` + 999 Gold. Leaving restores the
  player's real save slot (`restoreSaveSlot` in `store.ts`), so Continue never resumes a God Mode game, and a
  sandbox run's end never clears the real save.
- **Reducer actions** `godPrint` (any card into the shop, any tier, may exceed slot count) and `godGrantRune` (free
  rune / epic rune through the bought-rune path: the duplicate handling is now shared as `applyRuneCopyTo`). Both
  refused unless `run.godMode`, in the shop phase, with no modal open. `devGrant` stays DEV-only.
- **Gold refill + no clock:** the store tops Gold back to 999 below 900 after every committed action (a refused
  action stays a no-op); `shopClockInfinite` is true for God Mode whatever the DEV rules say; no timer plaque.
- **Round prompt:** End Turn asks "What round should your opponent board be on?" 1–15; a click fetches a random real
  board (`godBoards.ts`: Supabase `god_board_sample` → the boot pool → "No boards found") and fights it at once
  through the sandbox foe path (`servedBoards[wave]` + `sandboxFoeWave`).
- **God Mode panel** (`packages/ui/src/godMode/GodModePanel.tsx`): floating, draggable, collapsible; Minions /
  Spells / Runes / Epic runes with search, multi-select Tier + Tribe chips (spells ignore Tribe, "Neutral" chip),
  hover previews. Shop phase only; inert while a Discover / quest / Runeforge window is open. Search shared with
  the Scene Builder via `cardSearch.ts`.
- **Presentation exceptions to `sandbox`:** music and the good-luck intro play; the DEV Scene/Stage Builder panels
  never mount over God Mode; the lobby rail is hidden.

## The invulnerable-table decision

God Mode must never end on its own, but a God Mode run is a real lobby run underneath (the run machinery needs the
eight seats). Two options:

1. Special-case `lobby.finished` for God Mode. Rejected: a finished lobby stops settling rounds, which would freeze
   the player's own damage and every downstream per-round step.
2. **Chosen:** make the seven background seats `invulnerable` (the flag the Gauntlet already uses for its opponent)
   and lift `maxRounds` to 999. The lobby keeps settling normally, nobody else is ever eliminated, so it never
   finishes; only the player's own seat could end it, and God Mode plays on Unlimited health. The sim test plays 70
   rounds and stays in the shop.

## Supabase: deploy the RPC

`supabase/migrations/2026-10-08-god-board-sample.sql` adds `boards_wave_patch_idx` and
`god_board_sample(p_wave, p_set, p_patch_prefix)` (returns one snapshot `jsonb` or null; id-first uniform pick;
excludes synthetic and empty boards; `volatile`; anon-executable). **Deploy it in the SQL editor.** Until then the
client's RPC call fails and every pick falls back to the boards downloaded at startup (filtered by round, set and
non-synthetic origin, but not by game version). The call is annotated `// rows:` for the R-NET-01 1,000-row guard
(scalar RPC, never a table).
