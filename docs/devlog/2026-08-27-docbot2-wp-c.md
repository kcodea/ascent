# Doc Bot 2.0 — WP C: semantic trace + exact reproduction (instrumentation provably inert)

**PR:** `feat/docbot2-wp-c` · **Blueprint:** §7/§8/§23 · **Binding schemas:** `docs/docbot2/canonical-schemas.md` §1/§4

The highest-risk package of the §18 program, shipped behind its own neutrality proof. Nothing in this PR
touches `simulate.ts`, `types.ts`, `rng.ts`, the reducer's resolution order, `uidSeq`, or anything under
`packages/ui/src/fx|choreo|choreographer` / `presentation/policies.ts` — the exit-gate claim is not
"we were careful", it's a standing test lane.

## The neutrality lane (shipped first — everything else sits behind it)

`packages/sim/src/docbot/traceNeutrality.test.ts`:

- Identical seeded trajectories with capture ON (`reduceWithPresentation(_, _, true)` — the store/QA/ring
  chokepoint) vs OFF (plain `reduce`): byte-identical serialized state after EVERY step, identical final
  `rngCursor` and `uidSeq`, identical combat event logs.
- The ring rails (`hashRunState`, cursor reads) proven deterministic and mutation-free.
- The combat trace adapter proven pure (its input log byte-identical after adaptation; twice-adapted output
  identical).
- **Sabotage:** a simulated leaky tap (one extra rng draw per action) is caught by the comparison at the
  first affected step — the lane can actually fail.

## What shipped

1. **Combat trace adapter** — `packages/core/src/presentation/combatTrace.ts`. Pure post-hoc translation of
   `CombatResult.events` into the semantic envelope (`combatSemanticTrace`): deterministic
   `combat:<actionId>:<seq>` ids, source/target refs from structured fields only (never the `sc` narration
   string), cause from the existing `key`/`srcCard`/`avenge` stamps plus honest STEP GROUPING
   (`cause.stepRootEventId` — explicitly not proven parenting; true combat trigger-stack parenting remains
   the simulate()-chokepoint work of a later WP C wave). `COMBAT_TRACE_COVERAGE` is a
   `Record<CombatEvent['type'], …>` (type-exhaustive) of honest per-family claims, checked against real
   output by test — absent causality stays absent (§4.3).
2. **Unified trace** — `packages/sim/src/semanticTrace.ts`: recruit presentation events (already ~70% of the
   §7.3 target) + adapted combat lane; `serializeTrace` (byte-stable) + `firstTraceDivergence` (the
   comparison the timeline highlight and sabotage tests share).
3. **Always-on rolling action window** — `packages/ui/src/bug-report/actionRing.ts`: a 32-entry memory-only
   ring at the ONE commit chokepoint (`commitResolvedAction` — covers `dispatch` and the prepared-action
   commit). Each ACCEPTED action records `{action, rngCursorBefore, stateHashBefore, stateHashAfter}`
   (FNV-1a over `normalizeRunState`); presentation batches stay DEV-gated. Never in `RunState`, saves,
   `replayActions`, or replay frames. `BugIncidentCapsule` gains OPTIONAL `recentActions` (cloned + frozen
   at Ctrl+B); the 4 MB trim ladder drops it (recorded in `contextTruncated`) after `previousWaveFrames`.
   The Edge Function needs no change.
   **Cost, measured:** `hashRunState` ≈ 0.55 ms on a wave-10 state (~21 KB serialized; scales ~linearly with
   state size, dominated by `lastCombat`). One hash per accepted action (the before-hash reuses the previous
   after-hash via an identity cache), at human click cadence — never per frame. `npm run perf` unchanged
   (engine untouched).
4. **Exact report replay** — `packages/sim/src/windowReplay.ts` (`exactWindowReplay`): prefix rebuilt from
   seed, then every windowed action verified rail-by-rail; the FIRST divergent action is named (index +
   rail + recorded/observed). Wired into `bugs:repro` (`bug-qa-scenario.lib.ts` — window divergence ⇒
   `drifted` with the pinpoint) and the dev report panel. Pre-WP-C capsules: `applicable: false`, old path
   untouched. Replay is VERBATIM (no hermetic pin) — matching the recorded live run; the hermetic pin
   belongs to the scenario path below.
5. **QaScenarioV1 action trail** — optional `actions?: RecordedActionWindow[]` (mutually exclusive with
   `action`; recruit/lobby only; validated) + `observedSemantic?`. The runner executes trails through
   `reduceWithPresentation`, verifies rails per action (hermetic per-action wave pin, pin-then-record
   recorder contract), and reports `firstDivergence` (fails `ok`).
6. **Scene Builder timeline v0** — `BugScenarioPanel` (dev-only): the semantic trace as step-through text
   rows (◂/▸ cursor, deterministic ids in tooltips), plus the action window with an on-demand "⟳ verify"
   exact replay whose first divergent action is highlighted in place. No FX, no new visual systems.
7. **Sabotage (§4.5)** — dropped trace event and rewritten step-root both trip `firstTraceDivergence` at the
   exact doctored index; doctored `rngCursorBefore`/`stateHashAfter` ring entries make `exactWindowReplay`
   and the scenario-trail runner report divergence at the exact action; the leaky-rng tap trips the
   neutrality lane.

## Judgement calls (flagged for the owner)

- **Per-roll `rngRecords` (§4.4's makeRng tap) deferred.** The brief's deliverables need `rngCursorBefore`
  only, which is a plain state read; wrapping the generator is the riskiest possible instrumentation for
  zero exit-gate value today. The schema slot stays documented in `RecordedActionWindow`'s header.
- **Combat causal parenting stays grouping, not parenthood.** `stepRootEventId` is labeled evidence;
  faking parent ids would violate §4.3. The simulate() trigger-window instrumentation is a later WP C wave.
- **`buff.source` is a display label** in the log (emit sites pass names like 'Rune of Overflow') — carried
  as `label`, never coerced to a uid; recorded honestly in the coverage table.
- **Ring size 32** — the §18-C tuning knob; entries are a few hundred bytes each.
- No patch-notes entry: dev tooling only, nothing player-observable (the ring is memory-only diagnostics).
