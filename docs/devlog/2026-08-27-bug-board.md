# 2026-08-27 — Bug Board: the in-game bug inbox with priority + send-to-Claude

**Owner ask:** "a viewable in game screen for bugs so i can open our bug list in game, and then either
prioritize or hand pick bugs to fix first if i want, or just send the full stack to claude to fix."

## What shipped

- **`apps/web/bugBoardPlugin.ts`** — a dev-server-only Vite plugin (`apply: 'serve'`, the
  `rulebookPlugin` pattern) exposing three endpoints:
  - `GET /__bugboard/list` — all `bug_reports` rows minus the heavy `report` capsule (the 16 light
    columns), ordered `priority nulls-last, created_at desc`, plus a per-fingerprint dupe-count map.
  - `POST /__bugboard/update` — `{ id, status?, severity?, priority? }`, enum-validated server-side.
  - `POST /__bugboard/work-order` — `{ orderedReportIds, notes? }`: stamps `priority` 1..N in Supabase
    (durable copy first) and writes `.local/bug-reports/work-order.json`
    (`{ generatedAt, orderedReportIds, notes? }` — the FIXED contract the `bugs:pull` CLI reads).
  - Because it never ships in a build, it may hold the SERVICE-ROLE key: read from the untracked repo-root
    `.env` (`SUPABASE_SERVICE_ROLE_KEY`, hand-rolled parser), with `VITE_SUPABASE_URL` from
    `apps/web/.env`. Missing config → a structured 503 `not_configured` + hint, never a crash.
  - Pure planning/validation surface (`validateUpdate`, `planWorkOrderWrite`, `parseEnvFile`,
    `dupeCountsOf`) unit-tested in `bugBoardPlugin.test.ts`; the middleware is a thin shell.
- **`packages/ui/src/BugBoard.tsx`** — the overlay, DEV MENU → 🐛 Bug Board (mirrors the RulebookTriage
  wiring). Self-contained rows (quoted player text expandable past ~180 chars, issue-type icon,
  hero/wave/phase/mode/set/seed, patch, dupe ×N badge, status/severity selects that POST immediately,
  priority rank), filter pills (status / type / patch), three sorts (priority / newest / dupes),
  a hand-picked STACK (checkbox → ordered side panel with ▲▼/remove), and **Send to Claude**: the stack
  if one exists, else ALL open (`new`/`triaged`/`needs_info`) reports in the current sort. Confirmation
  names the exact next step: `work-order.json written — tell Claude: "fix the bug stack"`.
  Degrades gracefully when the endpoints 404 (prod) or report missing config.
- `.local/` added to `.gitignore` (local-only handoff artifacts).

## Decisions / judgement calls

- Stack reordering is ▲▼ only (no drag) — the panel is a short list and ▲▼ matches the row control;
  drag can come later if the stacks get long.
- The list response's dupe counts are aggregated in the plugin from the same listed rows (no second
  Supabase round trip, no PostgREST aggregate dependency).
- The board depends on nothing from the bug-reporter capture branches — it defines its own light
  `BugBoardRow` shape against the `bug_reports` columns, so it merges independently.

## Verification

Pure-helper tests (`apps/web/bugBoardPlugin.test.ts`) + jsdom component tests
(`packages/ui/src/BugBoard.test.tsx`: mocked list render, update POST body, default vs hand-picked
work-order ordering, 404 degrade). Full gate green.

No patch notes — dev tooling, not player-facing.
