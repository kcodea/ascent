# Doc Bot 2.0 — Work Package A: architecture reconciliation (docs-only)

**Date:** 2026-08-27 · **PR:** docs(docbot2) WP A · **Scope:** new `docs/docbot2/` directory, no
code changes.

The Doc Bot 2.0 blueprint (Codex handoff `DOCBOT_2_DEFINITIVE_QA_PLATFORM_HANDOFF.md`) opens with
Work Package A: map everything that exists onto the target architecture, pick canonical schemas,
and plan the migration before writing any platform code. This PR is that deliverable, built from
four verified architecture explorations of main (lanes, scenario system, rules registry,
events/content).

## What shipped

- **`docs/docbot2/current-state-map.md`** — ~49 capability rows (keep 22 / extend 24 / replace 1 /
  retire 2) plus ten reconciliation items D-1…D-10: the forked tripwire numbering, docbot.ts's
  deliberate second ratchet scan, the three QaScenario validators, the two divergent
  BugScenarioFile declarations, the two unrelated fingerprint systems (FNV finding identity vs
  SHA-256 report dedup — kept separate on purpose, boundary documented), the duplicated
  combatEventLines renderers, the legacy `scenario.json` retirement plan, and ten stale-doc fixes.
- **`docs/docbot2/canonical-schemas.md`** — the §18-A exit-gate decisions: QaScenarioV1 extended
  with optional capsule fields (action windows with per-action RNG records, expected/observed
  semantic outcomes, reportMoment, environment, provenance) — **no V2**; @game/rules extended
  toward RuleContract with the blueprint's 5-state status as a *derived view* over
  effectiveStatus + enforcement (47 decisions.json entries stay valid); DocbotFinding extended
  V2-compatibly (fingerprint untouched) with a staged plan to give the ~18 prose-only lanes
  machine output; SemanticEvent built by growing the existing recruit presentation envelope
  (already ~70% of the target) with combat joining via a thin adapter over the CombatEvent log;
  and `semanticRevision` = buildSha · `contentRevision()` (the existing-but-unused
  packages/content/src/revisions.ts hash) · rules-registry hash · schema versions.
- **`docs/docbot2/work-package-plan.md`** — the §19 vertical slice as its own stage, then WP B–H
  as agent briefs with exit gates and wave estimates. WP C (RNG-neutral trace instrumentation) is
  flagged highest-risk with six explicit proof obligations, led by a paired capture-on/off
  neutrality lane that ships before anything else.
- **`docs/docbot2/owner-review-pipeline.md`** — the 2–5s-per-answer review design:
  `corroborated` as a machine status distinct from `approved` (§23 honored; corroborated content
  is fully QA'd immediately, nothing blocks on the owner), convention clustering per the
  R-RUNEDUP precedent, a keyboard fly-through spec for RulebookTriage (which today has zero
  keyboard support), and a ~200-click / three-sitting budget computed from the real inventory
  (940 active objects, 856 policies / 28 families).
- **`docs/docbot2/README.md`** — the one-page program overview: §4 non-negotiables, §22
  non-goals, §21 DoD as the only end gate.
