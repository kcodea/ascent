# 2026-09-22 — Bug 23c340fb: Crest of the Climb folds spell power

**Player report (priority 2, text_mismatch, wave 2, Gambler, Set 2):** "crest of the climb not getting spell
power buffs". The capsule was the evidence: `spellBonus { attack: 0, health: 1 }` (a Coppercoat Spellsword
resolved on its Health option), then Crest cast on that Spellsword through `play → chooseOne 1 →
battlecryTarget`, and the landed buff record read `{ attack: 0, health: 4, source: 'Crest of the Climb' }`.
Deterministic and exactly what the content said: both branches carried `flat: true`.

## Why flat was never a ruling

The 2026-07-23 tranche-A devlog records the flat choice as a **flagged judgement call** ("chosen so the printed
numbers stay honest without wiring live Choose-One option text (a Tranche-C UI lift). Say if you'd rather they
scale."). The only reason was the missing live-text path, and that path exists since 2026-09-12
(`chooseOneBranchText`, #1441). The same "flat by the Crest precedent" reasoning was applied to Apples' shop
branch on 2026-08-02 and reversed by owner report on 2026-09-16 (#1525). Where the owner DID rule a stat spell
flat, the registry says so with the ruling id (Facetwright's `rubyStatGain`, `SPELL_POWER_EXCUSED`, 2026-08-26;
Tower Shield as a Gift, 2026-09-09). Crest has no such entry. The 2026-09-12 devlog's "the flat design stands
(owner-authored)" line and the matching patch-note bullet ("It is designed not to scale") restated the
implementation without a source; they are superseded by this entry and the new patch note.

## What shipped

- **Content:** `flat: true` removed from both Crest branches (`packages/content/src/cards/set1/spells.ts`).
  `spellBuffTarget` now folds the run's spell power into them like every other stat-granting Shop spell:
  "+4 Health" under +0/+1 power lands +5 Health; "+4 Attack" under the same power lands +4/+1 (the factory adds
  both bonuses to any grant, the Ales' rule).
- **Live text on every surface** (the hard rule):
  - The Choose One window greened automatically once the flag was gone (`chooseOneBranchTextFor` decides by
    `effectFoldsSpellPower`, not a card list).
  - The card's own text (shop / hand / hover / Discover, all through `liveCardText → spellDisplayText`) did
    NOT: `spellDisplayText`'s tail read `def.effects` only, and a Choose One spell keeps its grants in
    `chooseOne[].effects`. It now walks every branch that folds spell power through `spellBuffTarget` /
    `spellBuffAll` and greens that branch's own token in the card text, in the window's shape
    (`**Choose One:** give a minion **{{+4/+1}}**, or **{{+5 Health}}**.`).
  - The token rewrite (`liveStatToken`) is one shared helper for the window and the card, so the two surfaces
    cannot print different numbers for the same branch.
- **Comments** on `effectFoldsSpellPower`, `spellBuffTarget`, `chooseOneBranchTextFor` and Tower Shield no
  longer cite Crest as the flat example.
- **Patch note** (Balance, 2026-09-22): "Crest of the Climb scales".

## Verification

- `packages/sim/src/bugCrestClimbSpellPower.test.ts` (new, derived from the capsule): the exact sequence lands
  3/9 with a `{ health: 5 }` buff record (the capture had 3/8 and `{ health: 4 }`); the Attack branch lands
  7/5; every text surface prints the live number under +0/+1 and the authored text at zero power.
- `chooseOneBranchText.test.ts`: the "Crest never greens" pin is flipped to both branches greening; the
  single-stat shape test now runs on the real card; a SABOTAGE case pins the greened number to the reducer's
  delta for both branches.
- `spellBatch.test.ts`: a +1/+0 cast test plus the three `spellDisplayText` shapes.
- `spellPowerText.test.ts`: the "spell power is visible on every spell that gets it" sweep now reads Choose One
  branches too, so Crest, Apples and Aspect's Blessing are all swept from now on.
- All seven new/changed tests fail with the pre-fix content and pass with it.
