# Doc Bot 2.0 — WP H: the migration audit, probe retirement, and the final coverage report

The closing package of the Doc Bot 2.0 program (blueprint §18-H · §20 · §21 · §24.15). No engine changes,
no content edits, no owner-decision writes — this PR audits what was built, retires what the platform
genuinely superseded, and publishes the honest picture.

## 1. `npm run docbot:report` — the generated half

`packages/tools/src/docbot-report.lib.ts` + `docbot-report.ts`. One pass over the live registries —
contract sweep, text sweep, interaction graph + sweep + anomaly oracle, the rulebook, the retro citation
ledger, an fs roll-call of the docbot lanes — producing a typed `FinalReport`. Stamped with the commit and
the §16 `semanticRevision`, so a number can always be traced to the state it was measured under.

It lives in `packages/tools`, **not** `@game/sim`, for the same reason `semanticRevision.ts` does: it pulls
the 901-row contract registry and the whole rulebook (both pure data) and exporting it from the sim
entrypoint would ride them into the web bundle. That is current-state-map D-2's trap, and it is still real.
The one non-doc source change this PR makes is adding a `./semanticRevision` subpath to `@game/sim`'s
exports — the module's own docblock already said "QA lanes and tools import it by path", and `@game/rules`
sets the precedent with three subpaths.

Deliberately excluded: anything needing `playScan()`/`combatScan()`. The whole report costs ~0.3s, which is
what lets its drift rail ride the PR gate (187ms in vitest — the §17.1 Doc Bot budget is 30s).

## 2. `docs/docbot2/final-report.md` — the prose, drift-gated

Every headline number in the document is derived by the generator, and
`packages/tools/src/docbot-report.test.ts` re-derives all 25 of them on every PR. A number that moves
without the doc moving fails the gate and names the line. Two sabotage tests prove the rail can fail: a
doctored number and a dropped generator citation must both be caught. `npm run docbot:report -- --check`
runs the same check by hand.

**The §21 Definition of Done: 5 done · 11 partial · 0 not-started.** The two partials that most limit any
claim about this platform:

- **item 5** — 901/901 objects have a contract, but only **36** had a case a driver directly executed this
  sweep; **402** applicable cases have no driver at all. Lane citations are real evidence and are reported,
  but `runContractSweep` refuses to fold them into a contract's derived status, which is why the honest
  number is 36 and not a flattering four-figure one.
- **item 12** — the graduation loop is built, refusal-tested and CI-wired, but **zero real player reports
  have travelled it**. Everything we can say about it rests on the synthetic walkthrough.

Also honest: **534 unresolved parses** (59% of the corpus), **30** blocked interaction rows, **25 of 50**
docbot lanes carrying a sabotage proof, and combat causality that is *step grouping, not proven
parenthood* — `combatTrace.ts` says so itself, and the report repeats it rather than rounding it up.

## 3. Probe retirement — the D-1…D-10 dispositions

Full table in the report's §9. The two actually retired here:

- **D-1, the tripwire numbering fork.** Three pairs of lanes claimed the same number (14 = interactionMatrix
  *and* textOracle; 15 = conservationLaws *and* heroPowerLane; 16 = combatModLane *and*
  interactionFamilyMatrix *and* combatModScan). Numbers stripped from every lane header, registry docblock
  and doc; a lane's id is now its file basename — which is already the `ENFORCEMENT_LANES` key, and cannot
  collide. Comment-only: no lane's behaviour changed.
- **D-10, `docbot.ts`'s inventory label drift.** The "landed 2026-08-27 … each gates in npm test" caption was
  wrong for two rows when written and got wronger as WP B–H landed lanes it never listed. It is now an
  accurate lane roll-call, and **thirteen missing platform lanes were added** (vertical slice, contract
  extraction, semantic trace, trace neutrality, text parse, interaction graph, interaction sweep, anomaly
  oracle, curated regressions, bug taxonomy, findings ledger, graduation refusals, final report). The
  command list gained `docbot:text`, `docbot:interactions`, `docbot:ledger`, `docbot:report`,
  `contracts:extract` and `bugs:graduate`. An unlisted lane is an invisible lane — the exact failure this
  existsSync roll-call exists to prevent.

The kept-with-reason rows are decisions, not omissions: **D-2** (ratchetScan) is still bundle-necessary;
**D-3** (three scenario validators) is layered by trust domain; **D-5** (two fingerprint systems)
fingerprints two different things in two different trust domains and `bugs:graduate` already records the
pair. **D-8** (legacy `scenario.json`) is a *keep* only because its one-release overlap was declared the
same day as this audit — no release has passed. **D-6** (two `combatEventLines`) is a convert-deferred: the
two functions return different shapes today, and unifying them is a cross-seam refactor into Mike's
package, not a WP H cleanup.

## 4. Stale docs closed (D-9: 6 of 10)

`docs/docbot.md`'s "eight tripwires" line; the corpus digest now cites the command instead of a count
(CONTENT.md doctrine); `retro/README.md` now points at `retroInteractionMap.ts` + `npm run docbot:report`
instead of carrying counts that rot; the **THREE RULES** of a QA scenario (one engine / no executable
expectations / deterministic results) now live in `docbot2/README.md` instead of only in a docblock;
`metadata.commit` is documented as deprecated in favour of `semanticRevision`, which is what every producer
actually stamps. The four still open are all tied to D-8's retirement and go with it.
