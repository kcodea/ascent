# 2026-10-13 — Versus (real-time 1v1): Phase 0, the server resolver

Versus is a new unranked, real-time 1v1 mode (blueprint: `docs/superpowers/specs/2026-10-13-versus-mode-design.md`,
used loosely; the owner's 2026-10-13 rulings override it: 7 hearts, a lost round strikes one, draws strike nobody,
Resolve is never touched; random hero pick on timeout; duplicate heroes allowed and hidden; 30 s gate window back to
Open; 30 s disconnect pause then the opponent may unpause, the absent board auto-plays, 3 missed rounds forfeit;
timeouts make a random legal pick, never a cancel; up to 20 spectators, always on; XP, achievements and match
history yes, rating never; no rematch room, a continuous lobby room with seat swapping).

## Phase 0 — prove the server runs the exact client combat

- **The seam is promoted.** `mirrorForEnemySeat` moved from `sim/balance/seatRunner.ts` to the shipped
  `packages/sim/src/versus/mirror.ts` (seatRunner re-exports it; nothing in the balance bot changed).
  `packages/sim/src/versus/combat.ts` is the one-fight resolver: `resolveVersusFight({ matchSeed, round, p1, p2 })`
  runs `simulate()` once over two `faceOmen { deferFight }` sides and returns each seat's own perspective, the
  winner and who loses a heart. Fights land with `damageTaken: 0`, so Resolve and Armor never move.
- **The chair.** `simulate` is not side-neutral (Pre-emptive Assault is player-only, tie-breaks differ), so p1 sits
  as `player` on odd rounds and p2 on even ones, except that the only seat holding an armed attack-first takes the
  chair so its rune is honoured. Both holding it: the rotation decides (the other's bank is spent unused, the same
  kept asymmetry the balance table documents).
- **The bundle.** `npm run versus:bundle` esbuilds `packages/sim/src/versus/server.ts` (core + content + the
  resolver, platform neutral, about 1.5 MB) into `supabase/functions/versus-resolve/engine.generated.js`
  (gitignored, rebuilt before every deploy). A test pins that the entry pulls no reducer, run state or UI module.
- **The function.** `supabase/functions/versus-resolve/index.ts`: `health` and `parity` actions (pure computation,
  body capped at 600 KB, protocol and content revision checked, 409 on mismatch). `finalize` arrives with Phase 1.
- **The proof.** `packages/sim/src/versus/fixtures/parity.v1.json`: 13 real prepared-side pairs from greedy
  self-play (sets 1, 2 and 3, rounds 1 to 14). `npm run versus:parity -- bundle` re-resolves each in Node from
  source and compares the canonical result text with the bundle's, byte for byte: 13/13 identical.
  `npm run versus:parity -- remote <function url>` does the same against the deployed function.

Deno is not installed on this machine and Docker was not running, so the local proof is Node source vs the neutral
bundle; the Deno proof is the `remote` run against the deployed function.

Deployed by the coordinator (content 2041cfe8, protocol 1): `npm run versus:parity -- remote ...` returned 13/13
byte-identical against the live Deno function. Phase 0 is proven.

## Owner ruling during the build: Pre-emptive Assault is out of Versus

"Pre-emptive Assault ... just remove this spell from versus." `poolOf` drops every card with the
`spellAttackFirst` effect when `mode === 'versus'` (shop, Discover, grants), and the resolver's chair is now the plain
odd/even rotation (p1 on odd rounds), which only decides seeded tie-breaks. The enemy-side combat asymmetries the
mirror notes list are owner-ruled bugs being fixed in `simulate()` by another agent; Versus does not work around them.

## Phase 1 — the playable mode (behind `versusEnabled()`)

- **Engine.** `RunMode 'versus'`: no Resolve damage on a lost fight, no course victory, no Resolve game over (the
  server ends the match). New action `landCombat { fight }` lands a server fight on a deferred run WITHOUT settling,
  so the ordinary replay → `settleCombat` → `resolveCombat` flow plays it. `packages/sim/src/versus/run.ts`:
  `createVersusRun`, the hidden hero offer (private seeds), the timeout policy `versusAutoResolve` (random legal
  pick per open decision, seeded by match/round/seat; cancel only when nothing is legal), `buildVersusCandidate`
  (clone only), `catchUpVersusRun` (reconnect).
- **Server.** `supabase/migrations/2026-10-13-versus.sql` (additive): `versus_rooms`, `versus_members`,
  `versus_matches`, `versus_seat_private`, `versus_submissions`, `versus_rounds`, `versus_spectator_frames`, RLS
  (reads only; private seeds and candidates owner-only), security-definer RPCs for every transition, the round
  timer mirrored from `standardTurnSeconds`, pause/resume with deadline shift, unpause to auto, the 3-missed-round
  forfeit, the continuous room. Realtime publication adds for rooms, members, matches, rounds. The Edge Function's
  `finalize` action fights the two final sides once and commits through `versus_commit_round` (idempotent).
- **Client.** `packages/ui/src/versus/`: `versusRemote` (RPC + Realtime), `versusStore` (the session controller),
  `VersusTitle` (browser, room, gate gems, hero pick), `VersusHud` (hearts, waiting / pause / end layers),
  `spectatorView` (keyframe + delta protocol with explicit removals and gap recovery; Phase 2 renders it),
  `versusEmotes` (the emote seam: `{emoteId, seat, phase, offsetMs, round}` on the match channel's `emote`
  broadcast). The main store's only Versus contact is `versusHooks.ts`: End Turn becomes `faceOmen { deferFight }`
  and the End Turn commit lands the round's fight in the same commit, so the screen never shows the previous fight.
- **The flow per round.** Shopping is local and instant. An idle, debounced candidate (built on a clone) keeps the
  server's copy fresh. End Turn (or the shared deadline) LOCKS: the final side and a checkpoint of the answered
  run go up; the shop shows "Locked in". When the round's fight is committed, the live run gets the same timeout
  answers, Recruit plays the real End Turn (its End-of-Turn beats), and the commit lands the fight. Returning to the
  shop acknowledges the barrier; the next shop opens for both at the server's `shop_starts_at`.
- **Isolation.** A Versus run never holds `ascent.save` or `saved_runs` (`isResumableRun` needs a lobby), never
  records a replay draft, never seats or uploads pool boards, never touches the rank queue, never shares perf;
  leaving the match screen restores the save slot. Every gate is pinned in `versusIsolation.test.ts`.
- **Tests.** `versusCombat.test.ts`, `versusRun.test.ts`, `versusSchema.db.test.ts` (18 cases on the real SQL in
  PGlite), `versusMatch.db.test.ts` (two scripted clients play a whole match through the real SQL and the real
  finalize handler to seven hearts, then a reconnect from a lock checkpoint converges), and the UI protocol tests.

### Not done / follow-ups

- **XP and achievements for Versus** need `settle_progression` and the `progression_results.mode` check to accept a
  Versus source: that changes existing objects, so it is outside the additive rule and needs an owner go-ahead.
- **Spectator viewer** (Phase 2): the stream is produced (broadcast `spectate` + persisted keyframes); the stands
  show the score and round only.
- **Broadcast trust**: deltas and emotes ride a public broadcast channel; a hostile client could spoof them (the
  rows stay authoritative). Private channels with Realtime authorization would close it.
- Manual two-browser test matrix (blueprint 13) not yet run against a live backend.

## Live two-browser test against the real backend (2026-10-14)

Two anonymous sessions (two origins on :5196) drove two full matches on the live project after the migration and
the redeploy: create, join, the 30 s gate expiry back to Open, start, both gems, Hero Select with one seat timing
out (auto pick), a turn-1 Discover left open at the deadline (random legal pick, round force-locked for both), an
early lock that waits, End Turn by the real gem, the 90 s combat cap fast-forwarding a player who never left the
fight, a closed tab pausing the match, the 30 s grace, Unpause, the absent board auto-playing (no wait for the
present player), a reconnect rebuilding the run from the last lock checkpoint plus committed rounds, a match to 7
hearts, back to the room, and a seat swap through the stands. A second match covered a reload mid-match (boot
resume) and leaving mid-match (forfeit).

Fixed from it (client only, no SQL change): unreadable dark text on the room's dark backdrop; the HUD covering the
combat ROUND banner (moved top right); the result card covering the deciding fight before it was watched (now waits
for the fight to settle); a returning player only seeing "Watch" (Versus now rejoins your room on open, and a
running match resumes at boot); pause detection slipping to ~20 s (now reconciled every heartbeat by the players);
every heartbeat re-reading the room for every member (member heartbeats now patch `last_seen_at` in place).
