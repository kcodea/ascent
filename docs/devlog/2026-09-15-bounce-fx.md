# Bounce FX — `ruby-bounce` (owner) + `spell-bounce` (placeholder), one ribbon per cross-target re-cast

Owner ask 2026-09-15: a "bounce" cue whenever a spell or Ruby is RE-CAST onto a DIFFERENT target as a
consequence of the original cast. **Cross-target only** (owner ruling): a same-target recast — Mirrorwing
"casts again", Nimbus / Yazzus / Cometius "casts an additional time", Rune of Resonance's extra Ruby on the same
minion, Prismcaster — does NOT play this; the owner is authoring a separate same-target cue later. Those paths
are untouched.

## The two defs

- **`ruby-bounce`** — copied VERBATIM from the owner's workbench export (`packages/ui/src/fx/defs/ruby-bounce.json`).
  Three layers: a `ribbon` on `travel` (source = the body the original cast landed on, target = the bounce
  recipient), a source `burst` at 0, a target `burst` at 300 ms. Off filters are omitted like the neighbouring
  defs — `filterStack.ts` declares every filter toggle `default: false`, verified. Not retuned.
- **`spell-bounce`** — **PLACEHOLDER: a palette-swap of `ruby-bounce`, owner to tune in the workbench.** Same
  three layers, same timings; only the palettes differ: the ribbon + source burst take `spell-cast.json`'s
  palette (`[8001469, 13186799, 15769855, 16777215]`), the target burst takes `spell-target.json`'s emitter
  palette (`[25754, 2116030, 4901119, 14743807]`). No new layers were invented.

Both are registered the way the neighbours are: the `defs/*.json` glob (`fxDefs.ts`) picks them up, they are
listed in `directCalls.ts` (`DIRECT_CALL_SITES`) and pinned by `directCalls.test.ts`, which re-derives the scan
from source — the play sites use two string literals per file (not a `kind → def` lookup) so the scan sees both.

## The signal — one hop per (original target → new target) cast, never batched

**Shop** (`RunState.bounceFx` + `bounceFxSeq`, modelled on `starformFx`): `recordBounceFx(state, kind, fromUid,
toUid)` in `packages/sim/src/state.ts` appends `{ kind: 'spell' | 'ruby', fromUid, toUid }` and bumps the seq;
it is a no-op when both ends are the same body (the cross-target rule lives at the signal). Cleared at the top
of `reduce` like every per-action FX channel. `fromUid` may be a SHOP offer's uid (Rune of Distillation, Star
Crash on the Starform token); `anchorsForUnits` reads both rows so the UI resolves it the same way.

**Combat** — the `buff` event gains an optional, additive `bounce?: { from: string; kind: 'spell' | 'ruby' }`
(`packages/core/src/types.ts`, the shared boundary — called out in the PR). `CombatContext.buff` takes it as an
optional 6th argument; `simulate.ts` spreads it in only when set, so every other buff event is byte-identical.
`applyRubyStats` threads it. Stamped at: Trouble's self-Ruby (`from` = the body the triggering Ruby landed on),
Candle Conduit's extra landing, the combat arena's `gainRubyStats` (Resonance Idol), and Reflector's combat
Ruby half (which deliberately stays a plain `ctx.buff`, not `applyRubyStats` — no gameplay change).
No combat SPELL spread exists today, so the combat channel only ever sees Ruby hops.

## Presentation

- Shop: a `bounceFxSeq` watcher in `Recruit.tsx` groups identical hops into stacks and walks them with the Ruby
  sweep's cascade (`RUBY_GAP_MS` between distinct pairs, `RUBY_BEAT_MS` within a doubled one), retrying up to
  ~40 frames for a body that mounts a frame late. Skips a hop whose ends are gone rather than firing at the corner.
- Combat: a new `bounceFx` channel (`choreo/channels/bounce.ts`, pure `bouncesIn`) scored on exactly the kinds
  `rubyFx` is (`attackExchange`, `shout`, `buffWave`), same cascade-of-stacks, anchors resolved inside the timer.

## Skipped, and why

- Same-target recasts (Mirrorwing, Nimbus, Yazzus, Cometius, Constellation Prime's extra primary land, Rune of
  Resonance, Prismcaster, Living Grimoire): owner ruling — a separate cue is coming.
- **Ruby Transfer** (`recruit.ts` ~7446): stats change hands, nothing is cast (it is deliberately NOT routed
  through `fireOnRubyPlayed`) — a transfer, not a bounce.
- Rune of Spellhide (re-cast at Start of Combat on the SAME Beast) and Rune of the Spellmarket (copies the
  DELTA to a Shop offer as a buff, not a cast): neither is a re-cast onto a different target.
- Water Dragon's rune ("also cast the left-most spell in your hand"): a fresh cast with no original target.
